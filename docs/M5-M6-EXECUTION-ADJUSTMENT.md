# M5 收尾与 M6 并行执行

执行方：Codex。现有开发分支保留已验证的源码、安装包、失败记录和修复证据。开放 PR 已覆盖 Codex 版本准入、进程生命周期、Mock 调度和独立候选验收。复用这些实现与各自冻结 SHA 的证据。

## M5 唯一退出清单

以 [M5 最终清单](M5-FINAL-ACCEPTANCE.md) 的 M5-01 至 M5-05 为准。

| 分类 | 剩余事项 |
|---|---|
| BLOCKER | B1 真实进程的授权、费用和隔离边界，B3 真实进程的凭据、输出与审计边界。B2 在启用高风险应用前必须关闭，现阶段保持该能力关闭。 |
| REQUIRED | B6 为一次独立 Work 核验，绑定同一冻结 SHA，覆盖五项要求的适用证据并记录跳过原因。B4 和 B5 沿用已核验的限定证据。 |
| DEFERRED | D1 原工作区直接应用、D2 面向 Agent 的自动验证接线、D3 双 Agent 接力等后续阶段工作、D4 非当前发布目标的增强、D5 历史材料整理。 |

退出条件是独立核验五项的适用证据，处理拟启用能力的所有 BLOCKER 并满足 REQUIRED。仅在发现可复现的安全阻断缺陷时增加修复。

## M6 到 M7

1. 独立分支复用 Codex 公开 CLI 的版本准入、固定计划、进程适配器和 Core 绑定。先核对启动、观察、结果和超时取消的现有接口及缺口，只补会影响单 Agent 闭环的部分。
2. 并行完成可离线验证的任务绑定与失败处理。真实运行依赖 B1/B3 和明确的无额外费用条件。单 Agent 验收需要一份真实进程到 Core 的可复核结果。
3. 单 Agent 闭环通过后，接入第二个真实客户端。验证分配、授权上下文、交接、冲突检测、独立验收与失败恢复。结果在独立审核前保持未验证。

每个冻结产品 SHA 保存一套证据。文档只审差异，代码或测试变更只跑受影响范围和必要回归。本地执行测试，GitHub 保存成果与管理 PR。
